# 88-ANOS 并发性能评估与飞书迁移路径 V1.0

**审计日期:** 2026-06-03  
**场景:** 250名员工并发使用 ANOS Portal  
**当前架构:** Next.js 15 + Hono 4 + SQLite (better-sqlite3)

---

## 一、当前架构 250 并发评估

### 1.1 瓶颈分析

| 组件 | 250并发表现 | 瓶颈点 |
|------|-----------|--------|
| **Next.js Portal** | 🟢 可承载 | SSR/CSR分离，静态资源 CDN 友好 |
| **Hono API** | 🟡 单进程风险 | Node.js 单线程，CPU密集型操作会阻塞 |
| **SQLite** | 🔴 **致命瓶颈** | 单文件写入锁，250连接同时写入 → 大量 SQLITE_BUSY |
| **better-sqlite3** | 🔴 同步API | 每个请求创建新连接，无连接池 |

### 1.2 具体表现预估

```
250 用户并发操作:
├── 150 人浏览 Portal 页面     → 🟢 OK (Next.js SSR, 无DB操作)
├── 50 人查询/搜索             → 🟡 WAL模式下读并发 OK
├── 30 人创建 Inquiry          → 🔴 SQLITE_BUSY 排队
├── 15 人上传文件+解析          → 🔴 写入锁冲突
└── 5 人 Agent 建议请求        → 🟡 取决于 LLM API 延迟

预估结果: 写入密集型操作 50%+ 失败率
```

### 1.3 SQLite 写入锁机制

```
better-sqlite3 单连接:
  写操作 → 独占锁 → 所有其他写操作等待
  WAL 模式: 读操作不阻塞, 但写操作串行化
  
  250人场景: 每秒可能有 30-50 个写请求 → 排队严重
```

---

## 二、解决方案：三阶段迁移

### Phase 1: 快速优化（当前 → 支持 50 人试运行）

| 优化 | 效果 |
|------|------|
| **连接池** — 单例 Database 实例，所有路由共享 | 减少连接创建开销 |
| **WAL 模式** (已启用) | 读不阻塞写 |
| **写操作队列** — 串行化写入 | 消除 SQLITE_BUSY |
| **读操作缓存** — 5 秒 TTL | 减少重复查询 |
| **PM2 cluster 模式** — 多进程 | Node.js CPU利用率提升 |

**优化后:** 可支持 **50人** 试运行，写操作排队 < 200ms

### Phase 2: 飞书多维表格过渡（支持 100-250 人）

**飞书多维表格作为 Middleware 替代自建 SQL：**

```
ANOS Portal (Next.js)
       ↓
ANOS API (Hono)
       ↓
┌──────────────────────────┐
│  SQLite (写入缓冲层)      │  ← 本地缓冲 500ms
│  → 飞书多维表格 (主存储)  │  ← 飞书扛并发读写
│  → 飞书 API (异步同步)    │  ← 后台批量同步
└──────────────────────────┘
```

**飞书多维表格的能力：**
- 飞书自建分布式存储，天然支持高并发
- API 限流: 100次/秒/应用（企业版更高）
- 250人场景下，飞书 API 响应 < 500ms

**迁移成本:**
- 8张表已在飞书侧建立（运行 `scripts/feishu/create-bitable-tables.ts`）
- API 层增加飞书适配器（替换 SQL 查询 → 飞书 API 调用）
- 预计工作量：2 周

### Phase 3: PostgreSQL Middleware（支持 500+ 人）

当企业规模达到 500+ 人，或需要：
- 复杂关联查询（JOIN/子查询/聚合）
- 事务一致性要求高
- 审计日志量超过飞书承载

迁移到 PostgreSQL：
```
ANOS API (Hono)
       ↓
┌──────────────────────────┐
│  PostgreSQL (主存储)      │  ← Drizzle ORM 直接切换
│  + Redis (缓存)           │  ← 热数据毫秒级响应
│  + 飞书多维表格 (协同层)  │  ← 保留飞书协同优势
└──────────────────────────┘
```

## 三、飞书多维表格创建 — 立即执行

### 3.1 前置准备（需人类完成）

1. **飞书开放平台** → 创建企业自建应用
2. 获取 `FEISHU_APP_ID` + `FEISHU_APP_SECRET`
3. 应用权限: `bitable:app` (多维表格读写)
4. 创建 ANOS Data Hub 飞书空间

### 3.2 执行创建

```bash
# 预览建表结构
npx tsx scripts/feishu/create-bitable-tables.ts --dry-run

# 导出 JSON (给飞书妙搭导入)
npx tsx scripts/feishu/create-bitable-tables.ts --json > anos-tables.json

# 生产创建 (需要环境变量)
FEISHU_APP_ID=xxx FEISHU_APP_SECRET=xxx npx tsx scripts/feishu/create-bitable-tables.ts
```
