# 第1章 实施原则

ANOS第一阶段基于飞书生态落地，原则如下：

- 飞书原生优先。
- 先盘点，后建设。
- 先P0业务闭环，后扩展平台能力。
- 所有数据、知识、Workflow、Portal组件必须可追溯Owner。
- 所有来源、时间、权限、审计字段必须从第一天纳入设计。

# 第2章 飞书资源盘点

资源盘点对象：

| 类别 | 示例 |
| --- | --- |
| 数据资产 | 多维表格、历史Excel、ERP导出表 |
| 知识资产 | 飞书知识库、云文档、SOP、培训资料 |
| 流程资产 | 审批流、自动化、任务流 |
| 沟通资产 | 群聊、会议纪要、消息记录 |
| 应用资产 | 妙搭页面、飞书应用、Aily智能体 |

每项资产登记字段：

- AssetID
- AssetName
- AssetType
- Owner
- Department
- SourceURL
- PermissionScope
- UpdateCycle
- BusinessValue
- MigrationPriority

# 第6章 Portal实施手册

详细实施规范见 [75-飞书Portal实施手册 V1.0.md](75-飞书Portal实施手册%20V1.0.md)，统一智能入口详见 [76-统一智能入口AI Inbox设计规范 V1.0.md](76-统一智能入口AI%20Inbox设计规范%20V1.0.md)。

Portal建设原则：

- AI First，不以菜单为中心。
- 角色驱动，不以功能模块为中心。
- 三纵列布局。
- 全局保留Universal AI Input Bar。
- 所有核心卡片必须展示Source Card。

实施顺序：

1. 销售工作台
2. 采购工作台
3. 风控工作台
4. AI Inbox
5. CEO驾驶舱
6. 知识中心
7. Agent中心

# 第7章 Source Card统一规范

所有页面和Agent输出统一展示Source Card。

字段：

- Source
- SourceType
- SourceOwner
- EventTime
- CapturedAt
- VerifiedBy
- ConfidenceScore

适用对象：

- 客户需求
- 供应资源
- 知识文档
- 市场情报
- 风险事件
- Agent结论
