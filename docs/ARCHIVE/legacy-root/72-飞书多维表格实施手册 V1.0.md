# 第1章 建设原则

ANOS多维表格建设不是一次性建设100张表。

正确方式是：

```text
核心表先建
业务先跑通
Agent先产生价值
再逐步扩展
```

建设顺序采用：

```text
P0 → P1 → P2
```

P0聚焦销售、采购、风控闭环；P1补齐订单、库存、信用；P2建设画像、情报、知识和智能层。

# 第2章 多维表格总体架构

建议在飞书中建立统一空间：

```text
ANOS Data Hub
```

目录结构：

```text
ANOS Data Hub
├── 01 Master Data
├── 02 Trading Data
├── 03 Finance Data
├── 04 Intelligence Data
├── 05 Knowledge Data
├── 06 Agent Data
└── 07 Governance Data
```

命名要求：

- 表名使用英文对象名，便于API、Agent、Workflow调用。
- 视图名可使用中文，便于业务人员理解。
- 字段名遵循数据字典，不直接照搬ERP字段。

# 第3章 P0第一阶段建表范围

P0目标是在90天内跑通：

```text
客户需求
↓
供应资源
↓
供需匹配
↓
报价建议
↓
AR风险预警
```

## 01_Customer_Base

客户主数据。

| 项目 | 说明 |
| --- | --- |
| 负责人 | 销售总监 |
| 数据来源 | ERP、CRM、Excel |
| 记录粒度 | 一客户一记录 |
| 唯一主键 | CustomerID |

## 02_Supplier_Base

供应商主数据。

| 项目 | 说明 |
| --- | --- |
| 负责人 | 采购总监 |
| 数据来源 | ERP、采购资料、供应商清单 |
| 记录粒度 | 一供应商一记录 |
| 唯一主键 | SupplierID |

## 03_Product_Base

产品主数据。

| 项目 | 说明 |
| --- | --- |
| 负责人 | 产品中心 / 采购部 |
| 数据来源 | ERP、产品资料、品牌资料 |
| 记录粒度 | 一型号一记录 |
| 唯一主键 | MPN |

## 04_Inquiry_Base

需求池。

来源：

- 邮件
- 微信
- WhatsApp
- Excel
- 截图
- PDF

统一进入：

```text
Inquiry Intake Center
```

## 05_Supply_Resource_Base

供应资源池，P0新增重点表。

来源：

- 供应商报价
- 库存表
- 邮件
- 群聊资源
- 原厂通知

统一进入：

```text
Supply Intake Center
```

## 06_Opportunity_Base

商机池。

来源：

```text
Demand
+
Supply
```

由Matching Engine自动生成，负责人为AI Matching Engine和对应业务Owner。

## 07_AR_Risk_Base

应收风险池。

| 项目 | 说明 |
| --- | --- |
| 负责人 | 财务部 + 风控Agent |
| 数据来源 | ERP、金蝶、收款记录 |
| 记录粒度 | 一笔应收或一项风险一记录 |

# 第6章 字段命名规范

禁止混用：

```text
客户名称
Customer Name
客户name
```

统一采用PascalCase：

```text
CustomerName
SupplierID
OpportunityID
RiskLevel
```

字段含义以 [20-ANOS企业数据字典V1.0.md](20-ANOS企业数据字典V1.0.md) 为准。

# 第7章 强制字段规范

所有核心表必须具备以下字段。

## ID字段

```text
RecordID
```

业务对象表还应具备独立业务ID，例如：

- CustomerID
- SupplierID
- InquiryID
- ResourceID
- OpportunityID

## 来源字段

```text
SourceType
SourceURL
SourceOwner
```

## 时间字段

```text
EventTime
CapturedAt
UpdatedAt
```

## AI字段

```text
ConfidenceScore
AIScore
AITags
```

## 治理字段

```text
Status
Owner
Department
VerifiedBy
VerifiedAt
```

# 第8章 Source First规范

所有记录必须回答：

```text
来源是谁？
什么时候产生？
谁录入？
谁验证？
可信度多少？
```

示例：

```text
MPN：STM32H743
来源：ABC Electronics
来源方式：Email
事件时间：2026-06-01
验证人：采购经理张三
可信度：95%
```

# 第9章 关联关系规范

禁止重复录入主数据名称。

必须通过关联字段连接：

```text
Inquiry → Customer
Offer → Supplier
SO → Customer
AR → SO
Opportunity → Inquiry + Supply Resource
```

所有业务表引用主数据，而不是重复存储主数据。

# 第10章 权限规范

第一阶段基于飞书组织架构设置权限。

| 角色 | 可读数据 |
| --- | --- |
| 销售 | Customer、Inquiry、Offer |
| 采购 | Supplier、Supply Resource、PO |
| 财务 | AR、AP、Credit |
| CEO | 全部 |
| Agent | 按工具和任务最小授权 |

敏感字段必须单独控制，包括价格、毛利、信用、付款、合同和质量异常。

# 第11章 数据质量治理

新增Data Health Score，评分范围0-100。

评分维度：

- 完整性
- 准确性
- 时效性
- 关联性
- 来源可信度

低分记录应进入数据治理视图，由Owner定期处理。
