# 第1章 验收原则

MVP验收不只看功能上线。

必须同时验证：

- 业务闭环是否跑通。
- 数据是否可追溯。
- Agent输出是否有依据。
- 权限是否受控。
- Workflow异常是否可处理。
- 一线人员是否能完成真实任务。

# 第2章 总体验收标准

P0通过条件：

- 8张P0表可用。
- 4条P0 Workflow可用。
- 3个P0工作台可用。
- 3个P0 Agent基础能力可用。
- ERP样例数据可导入或同步。
- Source Card覆盖核心对象。
- 高风险动作需人工确认。
- 审计日志可查询。

# 第3章 数据验收

| 项目 | 标准 |
| --- | --- |
| 必填字段 | 完整率不低于95% |
| 主键唯一 | 不允许重复 |
| 来源字段 | P0对象100%具备SourceType和CapturedAt |
| 关联关系 | Inquiry可关联Customer，Opportunity可关联Inquiry和Supply Resource |
| 数据健康度 | 低于60分记录进入治理视图 |

# 第4章 Workflow验收

| Workflow | 验收标准 |
| --- | --- |
| WF-000 | 输入信息可生成AssetID和分类 |
| WF-001 | RFQ样例可生成Inquiry |
| WF-002 | 供应资源样例可生成Supply Resource |
| WF-003 | 可生成Opportunity和MatchScore |
| WF-004 | 可生成AR风险等级 |

每条Workflow必须有成功、失败、重试和人工处理路径。

# 第5章 Portal验收

销售工作台：

- 可查看今日RFQ。
- 可上传RFQ。
- 可查看客户卡片。
- 可查看Source Card。

采购工作台：

- 可上传供应资源。
- 可查看资源评分和匹配度。
- 可查看供应来源。

风控工作台：

- 可查看AR风险榜。
- 可查看风险来源。
- 可确认处置建议。

# 第6章 Agent验收

Agent输出必须包含：

- 结论
- 依据
- 来源
- 时间
- 可信度
- 建议动作
- 是否需要人工确认

禁止出现无来源的关键建议。

# 第7章 权限验收

测试场景：

- 销售不能看到未授权毛利字段。
- 采购不能看到非必要客户敏感信息。
- Agent不能调用未授权工具。
- 普通用户不能导出敏感清单。
- SourceURL按权限显示。

# 第8章 集成验收

ERP导入验收：

- 样例文件可导入。
- 字段映射正确。
- 导入失败有日志。
- 重复记录可识别。
- 更新记录不覆盖AI增强字段。

# 第9章 性能与可用性

P0最低要求：

- 常规页面3秒内可打开。
- 单次上传解析任务可异步处理。
- Workflow失败不阻塞整个平台。
- 审计日志不影响业务操作。

# 第10章 测试数据

必须准备：

- 10个客户。
- 10个供应商。
- 50个产品。
- 20条RFQ。
- 20条供应资源。
- 10条AR风险。
- 5个异常样例。

# 第11章 试运行准入

进入试运行前必须完成：

- P0验收用例通过。
- 权限验收通过。
- 真实业务Owner确认。
- 已知风险清单已记录。
- 回滚和人工兜底方案已准备。
