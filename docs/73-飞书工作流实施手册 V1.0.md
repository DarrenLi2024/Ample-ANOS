# 第1章 Workflow定位

很多企业的ERP只是数据仓库。

ANOS中：

```text
Data Hub = 企业记忆
Workflow = 企业神经系统
```

核心链路：

```text
事件 Event
↓
Agent
↓
Workflow
↓
行动 Action
```

ANOS价值不在于存了多少数据，而在于让数据、Agent、人和业务行动流动起来。

# 第2章 Workflow分级体系

| 等级 | 类型 | 职责 |
| --- | --- | --- |
| L1 | 数据工作流 | 采集、解析、同步、更新 |
| L2 | 业务工作流 | 销售、采购、风控、质量流程 |
| L3 | 智能工作流 | AI分析、AI推荐、AI预警 |
| L4 | Agent协同工作流 | Sales、Procurement、Credit、Knowledge Agent协同 |

# 第3章 Workflow设计原则

## Event First

工作流应由事件触发，而不是依赖人工主动寻找任务。

示例：

```text
新增Inquiry
↓
自动触发RFQ解析
```

```text
新增Supply Resource
↓
自动触发供需匹配
```

```text
新增AR
↓
自动触发风险分析
```

## Human-in-the-loop

AI可分析、建议和生成草案，但高风险动作必须人工确认。

## Source First

所有工作流写入数据时必须保留来源、时间、Owner、可信度。

# 第4章 WF-000企业资产登记工作流

`WF-000 Asset Registration Workflow` 是所有信息进入ANOS前的总入口。

适用对象：

- 客户需求
- 供应资源
- 知识文档
- 会议纪要
- 群聊情报
- 原厂通知
- 风险线索

流程：

```text
采集
↓
分类
↓
编号
↓
版本化
↓
打标签
↓
来源登记
↓
入库
```

输出：

- AssetID
- AssetType
- SourceType
- SourceURL
- EventTime
- CapturedAt
- ConfidenceScore

# 第5章 P0工作流

触发：

执行：

```text

↓

↓

↓
结构化
↓
写入Inquiry Base
↓

```

## WF-002 Supply Intake Workflow

供应资源录入工作流。

触发：

- 报价单
- 库存表
- 微信群资源
- 邮件
- 原厂通知

执行：

```text
OCR
↓
MPN识别
↓
价格识别
↓
库存识别
↓
交期识别
↓
写入Supply Resource Base
↓

```

## WF-003 Opportunity Matching Workflow

供需匹配工作流。

触发：

```text
InquiryCreated
SupplyCreated
```

执行：

- 型号匹配
- 库存匹配
- 价格匹配
- 交期匹配
- 风险匹配
- 授权匹配

输出：

```text
Opportunity
```

写入：

```text
Opportunity Base
```

## WF-004 AR Risk Workflow

应收风险工作流。

触发：

```text
AR更新
```

执行：

- 账期计算
- 风险评分
- 预警生成
- 催收建议

输出：

```text
Low / Medium / High / Critical
```

# 第8章 Workflow标准结构

所有工作流必须具备：

| 字段 | 说明 |
| --- | --- |
| WorkflowID | 例如WF-001 |
| WorkflowName | 例如Inquiry Intake |
| Trigger | 触发器 |
| Input | 输入 |
| Action | 动作 |
| Output | 输出 |
| Owner | 负责人 |
| KPI | 考核指标 |
| AuditRequired | 是否必须审计 |

# 第9章 Source First工作流规范

所有工作流写入的数据必须保留：

- SourceType
- SourceURL
- SourceOwner
- EventTime
- CapturedAt
- UpdatedAt
- VerifiedBy
- ConfidenceScore

客户RFQ不能只保存：

```text
STM32H743
5000PCS
```

必须保存：

```text
来源：Email
发件人：BYD采购
原始时间：2026-06-01 10:31
采集时间：2026-06-01 10:35
```

# 第10章 Agent协同工作流

典型链路：

```text
客户RFQ
↓
Sales Agent解析需求
↓
Procurement Agent寻找资源
↓
Credit Agent检查信用
↓
Knowledge Agent寻找历史案例
↓
生成Opportunity
```

这类流程统一称为Multi-Agent Workflow。
