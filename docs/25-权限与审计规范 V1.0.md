# 第1章 权限原则

ANOS遵循最小权限原则。

权限不是只管人，也要管Agent、Workflow、API和数据导出。

原则：

- 角色权限和数据范围分离。
- 页面权限和字段权限分离。
- Agent必须作为受控主体。
- 高风险动作必须人工确认。
- 所有关键操作必须审计。

# 第2章 角色模型

P0角色：

- CEO / 管理层
- 销售
- 采购
- 财务/风控
- 系统管理员
- Agent

# 第3章 数据权限

| 数据对象 | 销售 | 采购 | 财务/风控 | CEO |
| --- | --- | --- | --- | --- |
| Customer | 读写自己负责客户 | 只读有限字段 | 读信用相关 | 全部 |
| Supplier | 只读有限字段 | 读写 | 读付款相关 | 全部 |
| Inquiry | 读写自己数据 | 只读关联需求 | 只读 | 全部 |
| Supply Resource | 只读匹配结果 | 读写 | 只读风险字段 | 全部 |
| Opportunity | 读写相关商机 | 读写相关商机 | 只读风险字段 | 全部 |
| AR Risk | 只读相关客户 | 不可见或有限可见 | 读写 | 全部 |

# 第4章 字段权限

敏感字段：

- 客户价格
- 供应商价格
- 毛利
- 信用额度
- 账期
- 回款
- 付款
- 合同
- 质量异常
- 非公开证据材料

敏感字段必须单独授权，不因页面可见而默认可见。

# 第5章 Agent权限

Agent权限包括：

- 可读对象
- 可写对象
- 可调用工具
- 可触发Workflow
- 是否需要人工确认

P0限制：

| Agent | 可执行 | 不可执行 |
| --- | --- | --- |
| Sales Agent | 创建Inquiry草案、生成报价建议 | 自动发送正式报价 |
| Procurement Agent | 创建Supply Resource草案、生成采购建议 | 自动创建PO |
| Credit Agent | 生成风险建议 | 自动冻结信用或停单 |

# 第6章 Workflow权限

Workflow必须有Owner。

Workflow执行高风险动作前必须检查：

- 发起人权限
- Agent权限
- 数据权限
- 是否需要审批

# 第7章 审计对象

必须审计：

- 登录和身份切换。
- 数据创建、修改、删除、导出。
- 字段权限变更。
- Agent调用。
- Workflow执行。
- 人工确认。
- API调用。
- 外部系统同步。

# 第8章 审计日志字段

Audit Log字段：

- AuditID
- ActorType
- ActorID
- Role
- Action
- ObjectType
- ObjectID
- BeforeValue
- AfterValue
- Source
- Timestamp
- IP / Device
- Result
- ErrorMessage

# 第9章 Source Card权限

Source Card可见性必须受控。

业务人员可见：

- SourceType
- EventTime
- ConfidenceScore

受限可见：

- SourceURL
- SourceOwner
- 原始附件
- 非公开证据材料

# 第10章 下载与外部分享

以下行为必须审批或审计：

- 导出客户清单。
- 导出供应商报价。
- 导出AR风险清单。
- 下载合同或附件。
- 外部分享知识库或文档。

# 第11章 权限待确认事项

- 销售是否可见全部客户还是仅负责客户。
- 采购是否可见客户名称。
- 毛利字段可见范围。
- SourceURL是否对一线员工开放。
- Agent调用外部通信工具的审批边界。
